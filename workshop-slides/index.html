Worktrees: The Foundation

Transition — now let's understand the key primitive.

What is a git worktree?

.git
One repo
|
main/
Working dir
|
feature-a/
Working dir
|
feature-b/
Working dir

One repo. Multiple checkouts. Each with its own branch.

Git worktrees have been around since Git 2.5 (2015). Most people don't know they exist.

Why worktrees matter for agents

Without worktrees

  • Agents fight over the same files
  • Branch switching chaos
  • Uncommitted changes get trampled
  • One agent at a time

With worktrees

  • Each agent has its own copy
  • Zero file conflicts
  • Parallel work is safe
  • Merge when done
The key insight: isolation is what makes parallelism safe.

The command

claude --worktree
  • Creates an isolated worktree with its own branch
  • Agent works in its own directory
  • It's just git — nothing magical
One flag. That's it. Demo time.

Key takeaway

Worktree = isolated branch + working directory

Each agent gets its own sandbox

Merge when done — just like a feature branch

Common pitfalls

  • Don't edit shared files across worktrees — merge conflicts
  • Start hard tasks first — give them more wall-clock time
  • Review before merging — agents make mistakes too

What are agent teams?

Claude Code coordinates a team lead + teammates

Team Lead
Creates tasks, coordinates
↓
Teammate 1
Own context
Teammate 2
Own context
Teammate 3
Own context
↓
Shared Task List + Mailboxes
This is a step up from manual parallel sessions. Claude Code manages the coordination.

Subagents vs Agent Teams

Subagents Agent Teams
Context Own window; results return to caller Own window; fully independent
Communication Report back to main agent only Teammates message each other directly
Coordination Main agent manages all work Shared task list with self-coordination
Best for Focused tasks — only the result matters Complex work requiring collaboration
Token cost Lower Higher
Use subagents when you just need a result. Use agent teams when agents need to talk.

My honest take

I use agent teams to get a plan built quicker

Spin up teammates to research, explore, validate different angles

Arrive at a solid plan faster

For implementation → worktrees and parallel sessions

Be real with the audience. Agent teams are great for planning, not great for implementation orchestration.

Where agent teams struggle

  • Higher-level orchestration across multiple features
  • Session resumption doesn't work with in-process teammates
  • Task status can lag
  • One team at a time
  • Still experimental
Don't oversell. These are real limitations.

Best practices

  • 3-5 teammates — sweet spot for coordination
  • 5-6 tasks per teammate — enough to stay busy
  • Each teammate owns different files — avoid conflicts
  • Start with research/review — build confidence first
Quick practical tips if they want to try agent teams after this session.
